Module 1Foundations

Why Loops? — The Game Loop Concept

A loop is just "repeat until done." In games, this is the Game Loop — the heartbeat of every game engine running 60 times per second, keeping your player's world alive.

The Mental Model

Real-World Analogy: Think of a conveyor belt at checkout — items (frames) keep moving through scan → bag → receipt until the belt stops. Your game does the same: input → update → render, forever.

🎮
processInput()
Read keyboard, mouse, controller every frame
⚙️
update()
Move entities, check collisions, run AI
🖼️
render()
Draw everything to screen, 60fps target
🔁
Loop
Repeat until player quits or game ends

The Game Loop — Every Engine Ever

GameLoop.java
// THE GAME LOOP — runs 60 times per second!
while (gameIsRunning) {
    processInput();   // 1. Read keyboard/mouse/controller
    update();         // 2. Move entities, check collisions
    render();         // 3. Draw everything to screen
}
💡
KEY INSIGHT

Without loops, you'd need to write render() 3,600 times for just one minute of gameplay. Loops let computers do the repetitive work so you can focus on the fun stuff.

Why Java Has Four Loop Types

Loop TypeBest ForGame Example
forKnown countSpawn 10 enemies, tick 60fps timer
whileUnknown countGame loop, resource gathering, input wait
do-whileRun at least onceMenu systems, retry logic
for-eachCollectionsRender all entities, check all bullets
Quick Check
In a game loop, which order correctly represents the three main phases?
Input must come first so we know what changed, then we calculate the new state, then we draw it. This is the canonical game loop order.

Module 2Counted Iterations

The for Loop — "I Know Exactly How Many Times"

Use the for loop when you know the exact number of iterations up front — inventory slots, level counts, countdown timers. The three-part header puts initialization, condition, and update all in one visible line.

Anatomy of a for Loop

FOR LOOP ANATOMY
int i = 0 ; i < 10 ; i++ → { body }
① init — runs once ② condition — checked every time ③ update — runs after each body ④ body — your code here
ForSyntax.java
for (int i = 0; i < 10; i++) {
    // body runs 10 times (i = 0,1,2,...,9)
}
//   ↑ init    ↑ condition  ↑ update

Module 3Condition-Driven

The while Loop — "Keep Going While True"

Use while when you don't know how many iterations you'll need — only when to stop. The condition is checked before each iteration. If it starts false, the body never runs.

for loop

When you know how many times

for (int i=0; i<10; i++)

Counter is built-in, clean syntax

while loop

When you know the stop condition

while (playerIsAlive)

Flexible, works for unknown counts

WhileSyntax.java
while (condition) {
    // body — condition checked BEFORE each iteration
    // if condition starts false, body NEVER runs
}

🎮 Example 1: Input Validation (Menu System)

🎮 Example 2: Resource Gathering (Idle Game Mechanic)

🎮 Game Dev Example
ResourceGathering.java
int gold = 0;
int workers = 3;
int targetGold = 1000;

System.out.println("⛏️ Mining gold... (target: " + targetGold + ")");

while (gold < targetGold) {
    gold += workers * 5; // each worker mines 5 gold/tick
    System.out.printf("Gold: %,d | Workers: %d%n", gold, workers);
    
    // Hire more workers at milestones
    if (gold >= 500 && workers == 3) {
        workers = 5;
        System.out.println("🎉 Hired 2 more workers!");
    }
}
System.out.println("💰 Target reached! Total: " + gold);
🚨
INFINITE LOOP DANGER

Always make sure something inside the loop eventually makes the condition false. A while(true) loop with no break will freeze your program — and your game!

Quick Check
If the condition is false when a while loop is first reached, what happens?
The while loop checks the condition BEFORE each iteration. If it's false immediately, the body is skipped entirely — zero executions. This is what makes it different from do-while.

Module 4Guaranteed Execution

The do-while Loop — "Run Once, Then Check"

The do-while loop guarantees the body runs at least once before checking the condition. Perfect for menu systems, retry logic, and any situation where you need one initial action before deciding to repeat.

The Key Difference

LoopChecks ConditionGuaranteed First Run?Use When
whileBefore each iteration❌ NoCondition may already be false
do-whileAfter each iteration✅ YesMust execute once regardless
DoWhileSyntax.java
do {
    // body runs FIRST
    // THEN condition is checked
} while (condition); // ← semicolon required!

🎮 Example 1: Retry Mechanism (Server Connection)

🎮 Game Dev Example
ConnectionRetry.java
int maxAttempts = 3;
int attempt = 0;
boolean connected = false;

do {
    attempt++;
    System.out.println("🔄 Attempt " + attempt + " of " + maxAttempts);
    
    connected = Math.random() < 0.3; // 30% success rate
    
    if (!connected && attempt < maxAttempts)
        System.out.println("❌ Failed. Retrying...");
        
} while (!connected && attempt < maxAttempts);

if (connected)
    System.out.println("✅ Connected to game server!");
else
    System.out.println("💥 Failed after " + maxAttempts + " attempts.");

🎮 Example 2: Play Again Prompt

🎮 Game Dev Example
PlayAgain.java
Scanner scanner = new Scanner(System.in);
String playAgain;

do {
    playGame(); // Your game logic here — always runs first!
    
    System.out.print("\n🎮 Play again? (y/n): ");
    playAgain = scanner.nextLine().trim().toLowerCase();
    
} while (playAgain.equals("y") || playAgain.equals("yes"));

System.out.println("👋 Thanks for playing!");
✅
WHEN TO CHOOSE do-while

Ask yourself: "Is it possible I should skip this entirely?" If yes → while. If no, it must happen at least once → do-while. Menu systems, first attempts, and initial prompts almost always use do-while.

Quick Check
You're building a "retry login" feature. The user must attempt login at least once. Which loop should you use?
The do-while guarantees the body (the login attempt) runs at least once before checking whether to retry. A while loop could theoretically skip the attempt entirely if the condition was somehow false from the start.

Module 5Collections Made Easy

Enhanced for Loop — "For Each Item in Collection"

The enhanced for (or "for-each") loop gives you clean syntax for iterating over arrays and collections. No index arithmetic, no off-by-one errors — just "for each item, do this."

ForEachSyntax.java
for (Type item : collection) {
    // use item directly — no index needed!
    // works with arrays, Lists, Sets, and more
}
Traditional for

Need the index variable

Can modify the array

Risk of off-by-one

Enhanced for

Cleaner, no index needed

Read-only (can't modify source)

Cannot skip or reverse

Quick Check
When should you use a traditional for loop instead of the enhanced for loop?
The enhanced for is read-only and index-free. Use a traditional for when you need i (to modify elements via arr[i] = x, to iterate backwards, or to skip certain indexes).

Module 6Grids & Matrices

Nested Loops — Grids, Boards & Tile Maps

Nested loops are the key to working with 2D data. Every tile map, game board, pixel buffer, and grid system in game development uses this pattern: outer loop handles rows, inner loop handles columns.

NestedPattern.java
for (int row = 0; row < rows; row++) {       // OUTER: rows
    for (int col = 0; col < cols; col++) {   // INNER: columns
        // Process cell [row][col]
        // Inner loop completes ALL columns before outer advances
    }
}
💡
MENTAL MODEL

Think of a book: the outer loop turns pages (rows), the inner loop reads each word on that page (columns). When you finish a row, you start the next one from the beginning.

🎮 Example 1: Tic-Tac-Toe Board

🎮 Game Dev Example
TicTacToe.java
char[][] board = {
    {'X', 'O', 'X'},
    {'O', 'X', ' '},
    {' ', 'O', 'X'}
};

System.out.println("  0 1 2");
for (int r = 0; r < board.length; r++) {
    System.out.print(r + " ");
    for (int c = 0; c < board[r].length; c++) {
        System.out.print(board[r][c]);
        if (c < 2) System.out.print("|");
    }
    if (r < 2) System.out.println("\n  -----");
}
// Output:
//   0 1 2
// 0 X|O|X
//   -----
// 1 O|X|
//   -----
// 2  |O|X

Module 7Precision Control

Loop Control — break, continue & Labels

Sometimes you need to exit a loop early or skip an iteration. break and continue give you precise control over loop flow — and labeled versions let you escape nested loops entirely.

StatementEffectCommon Use
breakExit the loop immediatelyFound what you were searching for
continueSkip to next iterationSkip invalid/null items
label: + break labelExit outer (nested) loopsFound in 2D grid, stop all loops

🎮 Example 1: Search Inventory (break)

🎮 Game Dev Example
InventorySearch.java
String[] inventory = {"Sword", "Shield", "Potion", "Key", "Map"};
String target = "Key";

for (int i = 0; i < inventory.length; i++) {
    System.out.println("  Checking slot " + i + ": " + inventory[i]);
    if (inventory[i].equals(target)) {
        System.out.println("  ✅ Found at slot " + i + "!");
        break; // Stop searching — we found it!
    }
}
// Checking slot 0: Sword
// Checking slot 1: Shield
// Checking slot 2: Potion
// Checking slot 3: Key
// ✅ Found at slot 3!

🎮 Example 2: Process Valid Items (continue)

🎮 Game Dev Example
LootProcessing.java
String[] loot = {"Gold", null, "Sword", "", "Potion", "Gem"};
int validCount = 0;

for (String item : loot) {
    if (item == null || item.trim().isEmpty()) {
        System.out.println("  ⚠️ Skipping empty slot");
        continue; // Skip to next item
    }
    System.out.println("  ✅ Added: " + item);
    validCount++;
}
System.out.println("Total valid: " + validCount);

🎮 Example 3: Labeled break (Find Player in Grid)

🎮 Game Dev Example
GridSearch.java
int[][] dungeon = {
    {0, 0, 0, 0},
    {0, 1, 0, 2}, // 1=Player, 2=Exit
    {0, 0, 0, 0}
};

int playerRow = -1, playerCol = -1;

searchLoop: // Label the OUTER loop
for (int r = 0; r < dungeon.length; r++) {
    for (int c = 0; c < dungeon[r].length; c++) {
        if (dungeon[r][c] == 1) {
            playerRow = r;
            playerCol = c;
            break searchLoop; // Breaks BOTH loops at once!
        }
    }
}
System.out.println("🧍 Player at (" + playerRow + ", " + playerCol + ")");
⚠️
USE LABELS SPARINGLY

Labels can make code hard to read. In production, consider refactoring the nested loop into a separate method that returns early. But for grid searches and game map traversal, labels are perfectly valid.

Quick Check
What does continue do inside a loop body?
continue skips the remaining code in the current iteration and jumps to the update step (for for loops) or rechecks the condition (for while loops). The loop itself keeps going — only that one iteration is cut short.

Capstone — Turn-Based Combat Prototype

Put it all together. This mini game engine uses every loop type you've learned — while for the main game loop, do-while for combat rounds, nested while for input validation, and for-each to iterate enemies.

Architecture Overview

🔄
while — Main Loop
Runs while game isn't over and there are enemies left
⚔️
do-while — Combat
Each combat round — always executes at least one turn
🖊️
while — Input
Validates menu choice, retries on invalid input
📋
for-each — Enemies
Iterates enemy list for wave setup and status

Full Combat Engine

CombatDemo.java
import java.util.*;

public class CombatDemo {
    record Entity(String name, int hp, int maxHp, int atk, int def) {}
    
    public static void main(String[] args) {
        Entity player = new Entity("🧙 Hero", 100, 100, 15, 5);
        List<Entity> enemies = Arrays.asList(
            new Entity("🐀 Rat",    30,  30,  8,  2),
            new Entity("🐺 Wolf",   50,  50, 12,  4),
            new Entity("🐉 Dragon", 200, 200, 25, 10)
        );
        
        Scanner sc = new Scanner(System.in);
        boolean gameOver = false;
        int wave = 1;
        
        // ════ MAIN GAME LOOP (while) ════
        while (!gameOver && wave <= enemies.size()) {
            Entity enemy = enemies.get(wave - 1);
            System.out.println("\n═══ WAVE " + wave + ": " + enemy.name() + " ═══");
            
            // ════ COMBAT LOOP (do-while) ════
            do {
                printStatus(player, enemy);
                
                // ════ INPUT VALIDATION (while) ════
                int choice = -1;
                while (choice < 1 || choice > 3) {
                    System.out.print("[1] Attack  [2] Heal  [3] Flee: ");
                    if (sc.hasNextInt()) choice = sc.nextInt();
                    else sc.next();
                }
                
                switch (choice) {
                    case 1 -> attack(player, enemy);
                    case 2 -> heal(player);
                    case 3 -> { System.out.println("🏃 You fled!"); gameOver = true; }
                }
                
                if (enemy.hp() > 0 && !gameOver) enemyAttack(enemy, player);
                if (player.hp() <= 0) { System.out.println("☠️ YOU DIED."); gameOver = true; }
                
            } while (enemy.hp() > 0 && player.hp() > 0 && !gameOver);
            
            if (!gameOver) { System.out.println("🎉 Defeated! +50 XP"); wave++; }
        }
        
        if (!gameOver) System.out.println("\n🏆 VICTORY! All waves cleared!");
        sc.close();
    }
}
